# ADR 003: Signal State Machine and Idempotent Execution

## Status
Accepted

## Context
Trading signals generated by AI models or quantitative engines must travel across network boundaries and execute on remote client terminals. Network drops, EA restarts, duplicate polling, or delayed acknowledgments can cause catastrophic duplicate trades or execution of expired stale signals.

## Decision
We define an immutable, deterministic state machine for all trading signals identified by UUIDv7.

### 1. State Machine Transitions
```
                ┌──────────────┐
                │   CREATED    │
                └──────┬───────┘
                       │ (Dispatched via Poll/Push)
                       ▼
                ┌──────────────┐
                │  DELIVERED   │
                └──────┬───────┘
                       │ (Received by EA Terminal)
                       ▼
                ┌──────────────┐
                │    ACKED     │
                └──┬────┬────┬─┘
                   │    │    │
      ┌────────────┘    │    └────────────┐
      │ (Executed)      │ (Rejected)      │ (TTL Expired)
      ▼                 ▼                 ▼
┌───────────┐    ┌────────────┐    ┌───────────┐
│ EXECUTED  │    │  REJECTED  │    │  EXPIRED  │
└───────────┘    └────────────┘    └───────────┘
```

- Any transition outside this state graph is illegal and rejected at the database / API layer.
- Terminal states (`EXECUTED`, `REJECTED`, `EXPIRED`) are immutable.

### 2. Idempotency Invariants
1. **Database Unique Constraints**: `signal_events` has a unique constraint `(signal_id, to_state)`. A signal cannot transition to the same state twice.
2. **Terminal Comment Tagging**:
   - When executing an order, the EA writes `AQ:<UUID>` into the MT5 `MqlTradeRequest.comment` field.
   - Before executing any signal, the EA scans open positions and recent history for the presence of the Signal UUID. If already found, execution is skipped and an `ACKED/EXECUTED` confirmation is returned.
3. **Strict TTL & Price Drift Limit**:
   - Every signal contains an explicit `expires_at` timestamp (default 30 seconds).
   - If current time $> \text{expires\_at}$, the EA flags `TTL_EXPIRED` and marks state `EXPIRED`.
   - If market price deviates by more than `maxDeviationPoints` from `reference_price`, the EA flags `PRICE_DEVIATION` and transitions to `REJECTED`.

## Rejected Alternatives
1. **Stateless Fire-and-Forget Dispatch**:
   - *Rejected* because backend cannot track order fills, slippage, or rejections, risking unsynchronized risk accounting.
2. **Client-Assigned Signal IDs**:
   - *Rejected* because signal generation is centralized and requires server-side sequencing and replay tracking.

## Consequences
- **Positive**: Impossible to double-execute trades across EA crashes or network replays; full audit trail with microsecond event timestamps; transparent execution diagnostics.
- **Negative**: Requires EA to maintain local history scan on startup.
